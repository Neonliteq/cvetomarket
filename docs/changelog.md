# История изменений проекта

Хронология работ (важное — для контекста новых сессий). Новые записи добавляйте сверху.

## Мобильная производительность: картинки и PWA-кэш
- **Все изображения из `uploads/` теперь запрашиваются через ресайз** (`?w=`): панель продавца (список товаров, позиции заказов, фото сборки, логотип, обложка), админка, чат, аватары в шапке и кабинете покупателя. Раньше эти места грузили оригиналы по 1–3 МБ — для продавца со смартфона это были десятки мегабайт.
- **Из предзагрузки Service Worker исключены чанки админки и кабинета продавца** (`Admin`, `ShopDashboard`, `SellerAuth`) — **−243 КБ** на первом визите у каждого посетителя. Догружаются по требованию и кэшируются рантайм-маршрутом `app-chunks`.
- Примечание: `vite-plugin-pwa` 1.2 **не поддерживает** `globIgnores`, поэтому фильтрация манифеста сделана в `client/src/sw.ts`.
- Что уже было в порядке: HTTP/2, Brotli, ленивые чанки по маршрутам, hashed-имена + immutable-кэш, ресайз картинок товаров, кэш nginx `/objects`. Сервер не перегружен (load average ≈ 0).

## Очистка диска при заполнении
- `scripts/cleanup-uploads.sh` — включается **только при заполнении диска выше порога** (по умолчанию 85 %). Удаляет **старые фото сборки заказов** (доставленные/отменённые, старше 30 дней) и временные файлы; опционально — «осиротевшие» файлы.
- Гарантированно **не трогает** фото товаров, логотипы/обложки магазинов, аватары, изображения в чатах, фото товаров в позициях заказов и черновики товаров — сверка идёт по БД.
- Cron: ежедневно в 04:10, лог `/var/log/cvetomarket/cleanup.log`. Есть безопасный режим `DRY_RUN=1`.
- Проверено на проде: 937 защищённых файлов, 14 кандидатов на удаление, среди них 0 файлов из карточек товаров.

## Полный отказ от S3: файлы только на диске сервера
- **Загрузка** (`POST /api/upload`) пишет файл только в `<APP_DIR>/uploads/<name>` — внешнее хранилище не используется.
- **Отдача** `/objects/uploads/<name>` перенесена в чистый модуль `server/objectRoutes.ts`: читает файл с диска, при отсутствии — заглушка (ресайз `?w=` и in-memory кэш сохранены).
- **Удалено:** папка `server/replit_integrations/` (S3-клиент, ACL, presigned-загрузка), мёртвый хук `client/src/hooks/use-upload.ts`, скрипт `scripts/backfill-local-uploads.ts` и npm-скрипт `backfill:uploads`.
- **Зависимости:** убраны `@aws-sdk/client-s3` и `@google-cloud/storage` (не использовались после перехода).
- **Добавлено:** `scripts/backup-uploads.sh` — архив `uploads/` с ротацией (3 копии), так как изображения теперь существуют только на сервере.
- URL-ы изображений в БД не изменились (`/objects/uploads/...`) — миграция не требуется.

## Упрочнение прода
- **Сиды** не выполняются на `production` (`NODE_ENV=production`) — на пустой боевой БД больше не создаётся демо-админ с известным паролем. Принудительно — `SEED_DEMO_DATA=true`.
- **Бэкапы БД**: `scripts/backup-db.sh` (pg_dump → gzip в `/var/backups/cvetomarket`, хранение 14 дней) + cron ежедневно в 03:30.
- **Домен приложения** вынесен в `APP_DOMAIN` (легаси-имена `REPLIT_DOMAINS` / `REPLIT_DEV_DOMAIN` поддерживаются).
- `server/unitpay.ts` помечен как неподключённая заготовка (вторая платёжная система).
- Удалены влитые feature-ветки — локально и на GitHub (осталась только `main`).

## Изображения
- **Файлы хранятся только на диске сервера** (`<APP_DIR>/uploads`); S3 убран полностью (см. раздел выше).
- Путь развития: S3 → таймауты и заглушка при сбоях → локальное зеркало с S3-резервом (перенесено 925 объектов, ~1.4 ГБ) → полный отказ от S3.
- On-the-fly ресайз в webp (sharp) + in-memory кэш; nginx кэширует `/objects` (10 ГБ, 45 дней).
- Архив изображений: `scripts/backup-uploads.sh`.
- Мобильная скорость: ресайз картинок, self-host шрифтов, HTTP/2.
