# История изменений проекта

Хронология работ (важное — для контекста новых сессий). Новые записи добавляйте сверху.

## Упрочнение прода
- **Сиды** не выполняются на `production` (`NODE_ENV=production`) — на пустой боевой БД больше не создаётся демо-админ с известным паролем. Принудительно — `SEED_DEMO_DATA=true`.
- **Бэкапы БД**: `scripts/backup-db.sh` (pg_dump → gzip в `/var/backups/cvetomarket`, хранение 14 дней) + cron ежедневно в 03:30.
- **Домен приложения** вынесен в `APP_DOMAIN` (легаси-имена `REPLIT_DOMAINS` / `REPLIT_DEV_DOMAIN` поддерживаются).
- `server/unitpay.ts` помечен как неподключённая заготовка (вторая платёжная система).
- Удалены влитые feature-ветки — локально и на GitHub (осталась только `main`).

## Подготовка к работе (текущее)

- Почищены локальные «gone»-ветки.

## Эксплуатация и стабильность
- **Логи PM2:** удалён устаревший файл `~/.pm2/logs/cvetomarket-out.log` (554 МБ); установлен `pm2-logrotate` (50 МБ, 5 файлов, сжатие, ежедневно). В `ecosystem.config.cjs` добавлен `merge_logs: true` — раньше каждый деплой плодил новые `out-N.log` (файлы-сироты).
- **Удаление пользователя в админке** падало на внешних ключах — `deleteUser` теперь чистит `notifications`, `notification_preferences`, `push_subscriptions` и легаси `bonus_transactions`.
- **PM2 cluster (2 воркера)** вместо fork; конфиг переведён в `.cjs` (проект ESM).
- **`deploy.sh`:** `pm2 stop` перед `npm ci` — иначе сборка на 2 ГБ RAM падала по OOM.

## Изображения
- **Локальное зеркало `uploads/`:** все файлы отдаются с диска сервера, S3 — только резерв. Загрузка пишет локально и best-effort в S3 (сбой S3 не ломает загрузку). Скрипт дозаполнения: `npm run backfill:uploads` (скачано 925 объектов, ~1.4 ГБ).
- До этого: таймауты S3, заглушка при сбое, on-the-fly ресайз в webp (sharp) + in-memory кэш, кэш nginx `/objects` (10 ГБ).
- Мобильная скорость: ресайз картинок, self-host шрифтов, HTTP/2.

## Оплата
- **Смена организации-получателя платежей:** ООО «Зеор» → **ИП Аршинская Елена Анатольевна** (ИНН 860231688514, ОГРНИП 320861700043258). Обновлены реквизиты на сайте и креды Robokassa в `.env`.
- **Исправлен флаг тестового режима:** код читал `ROBOKASSA_TEST`, а в `.env` было `ROBOKASSA_IS_TEST`, и сравнение шло строго со строкой `"true"` → тестовый режим не работал (всегда боевой). Теперь принимаются оба имени и значения `true/1/yes/on`.
- Подтверждена работа оплаты: тестовый заказ №34 на 2 ₽ → уведомление `[robokassa/result]` → `payment_status = paid`, `payment_id = robokassa:34`.

## Аналитика
- **Яндекс.Метрика** (счётчик `112737627`): сниппет в `<head>` с `defer: true`; просмотры SPA отправляются вручную на каждой смене маршрута (иначе считалась бы только первая загрузка).
